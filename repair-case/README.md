# 動かなくなったツールの復旧

「AIで作ったツールが動かなくなった」「作った人が退職して、直せる人が社内にいない」

——そんな状態になった業務ツール(スクレイパー / 自動化スクリプト / 社内API連携など)を、
最短3日で診断・修理し、再発防止の仕組みまで付けてお返しします。

## こんな状況、心当たりありませんか

- ChatGPTやAIツールに書いてもらったスクレイパー・GASが、ある日突然エラーで止まった
- 作った担当者(社員・業務委託・元インターン)がすでにいなくて、コードを読める人が社内にいない
- エラーメッセージを見ても、何が原因で・どこを直せばいいのか分からない
- 直したはいいが、また同じように壊れた時にどう気づけばいいのか不安
- そもそも仕様書もテストもなく、「動いていた」という事実以外に手がかりがない

## 私たちがやること(3日間の流れ)

**1日目: 診断**
実際にツールを動かして、本物のエラーログを取得します。「たぶんこれが原因」ではなく、
再現できたエラーとログの該当行を突き合わせて原因を特定します。

**2日目: 修理**
CLIの使い方・出力フォーマットなど、既存の利用者が困らないよう「外から見た挙動」は
できる限り変えずに、壊れた内部ロジックだけを直します。あわせて、エラーハンドリングや
タイムアウト、リトライなど、元のツールに欠けていた最低限の堅牢性も補います。

**3日目: 納品 + 再発防止**
実データで動作確認したログと診断レポートをまとめてお渡しします。可能な場合は、
「まだ壊れていないか」をワンコマンドで確認できるセルフチェック機能を追加し、
次に同じ状態になっても社内で気づけるようにします。

## 対象

- **GAS(Google Apps Script)**: スプレッドシート連携、定期実行トリガー、フォーム処理など
- **Python**: スクレイパー、バッチ処理、データ整形スクリプト
- **Node.js**: 定期実行ジョブ、簡易API、Webhook処理
- **スクレイパー**: サイト構造の変化で壊れたクローラー・収集ツール全般
- **API連携**: 外部サービス(決済・チャット・SNS・スプレッドシート等)とのつなぎ込みスクリプト

## 対象外

- 大規模なリプレイス・作り直しを前提とするプロジェクト(まずは復旧のご相談からどうぞ)
- 稼働中の基幹システム・決済処理など、障害時の責任範囲が大きく専門チームでの保守が前提のもの
- ソースコードが一切存在しない/実行環境ごと失われているケース(復元できる範囲を事前にご相談)
- 対象サービスの利用規約・法令に抵触する内容(スクレイピング対象サイトの規約違反など)

## 納品物

1. **動作するツール本体**(修正版のソースコード一式)
2. **診断レポート**(症状 / 原因 / 修正内容 / 動作確認結果 / 再発防止策をまとめたドキュメント)
3. **修正差分**(何をどう直したかが分かるdiff)
4. **実行ログ**(実データで動かした際の生ログ。口頭説明ではなく証跡としてお渡しします)
5. **(可能な場合)セルフチェック機能**: 次に壊れた際、専門知識がなくても「壊れているかどうか」を
   確認できるコマンド/仕組み
