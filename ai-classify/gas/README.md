# 問い合わせAI分類（Google Apps Script版）

アクティブなシートの問い合わせを10件ずつ分類し、結果をシートに保存します。Python版のプロンプト、`rules.example.yaml` のカテゴリ定義・緊急度・返信トーン、本文キーワードによるカテゴリ補正を移植しています。外部ライブラリは不要です。

## セットアップ

1. Googleスプレッドシートの1行目に `問い合わせ本文` ヘッダーを置き、2行目以降に本文を入力します。別名にする場合は `Code.gs` の `TEXT_COLUMN` を変更します。
2. **拡張機能 → Apps Script** を開き、`Code.gs` の内容をコピーして保存します。V8ランタイムを使用してください。
3. Apps Scriptの **プロジェクトの設定 → スクリプト プロパティ** に以下を登録します。

| プロパティ | 設定値 |
| --- | --- |
| `PROVIDER` | `openai` または `anthropic`（省略時は `openai`） |
| `OPENAI_API_KEY` | OpenAI利用時のAPIキー |
| `ANTHROPIC_API_KEY` | Anthropic利用時のAPIキー |
| `MODEL` | 任意。省略時はOpenAI: `gpt-4o-mini`、Anthropic: `claude-sonnet-5` |
| `CATEGORIES` | 任意。半角カンマ区切り。未設定時は下記の既定値を保存 |

```text
配送遅延,返品・交換,不良品,請求・領収書,使い方の質問,予約変更,クレーム,感謝・好意的な感想,営業・売り込み,採用問い合わせ,その他
```

4. エディタで `runClassification` を1回実行し、スプレッドシート操作・外部通信・トリガー作成を承認します。この初回実行から分類とAPI課金が発生します。
5. シートを再読み込みします。メニュー **AI分類 → 実行 / 設定を開く / ルール確認** が使えます。「設定を開く」のリンクからプロパティを編集できます。

APIキーはシートやコードに書かず、スクリプト プロパティに保存してください。スクリプト編集者はプロパティにアクセスできます。問い合わせ本文は選択したAPIプロバイダに送信されます。返信案はセルに保存するだけで、送信はしません。

## 出力と再実行

出力ヘッダーはPython版と同じ `カテゴリ / 要約 / 緊急度 / 返信要否 / 返信案` です。要約は40文字以内、緊急度は `高・中・低`、返信要否は `要・不要`。返信案は丁寧な日本語2〜3文（80〜150字程度をプロンプトで指定）です。

初回は本文列の右側に5列を挿入します。既存の連続した出力5列があれば再利用します。欠けたヘッダーはその列全体が空の場合だけ補い、既存データへの上書きを防ぎます。出力列が離れている場合は、上記の順で隣接するよう整理してください。

本文が空の行と、出力5セルのいずれかに値・数式がある行はスキップします。部分的に入力した結果も保護します。再分類したい行は出力5セルすべてを消して再実行してください。本文やルールを変更しても既存結果は自動更新されません。実行中は行の並べ替え・挿入・削除を避けてください。

カテゴリ名と順序は `CATEGORIES` に従います。既定名にはYAMLの説明を適用し、追加した名前には「その名前に関する問い合わせ」という説明を使います。詳細な独自定義はコードの `DEFAULT_RULES.categories` に追加できます。Python版と同じく、本文キーワードの最多一致カテゴリが一意ならモデルの選択を補正します。補正語は `TEXT_KEYWORDS` で変更できます。

応答はJSON配列として解析し、件数・重複ID・冒頭15文字の引用・カテゴリ番号・各値を検証してから保存します。不正応答ではそのバッチを未処理のまま停止します。Python版の分類失敗の代替値保存とは異なり、修正後に再実行できます。要約はPython版の保存時60文字ではなく、指定どおり40文字に制限します。

## 費用と実行制限

API利用料は選択したプロバイダ・モデルの入力／出力トークン量に応じて発生します。10件単位でプロンプトを共有しますが、本文が長いほど費用が増えます。料金表は固定で埋め込んでいません。各プロバイダの管理画面で料金・利用量を確認してください。HTTP 429／5xxは指数バックオフと `Retry-After` に従い最大4回試行します。途中で失敗したAPI呼び出しや、保存前に実行が終了したバッチは、再実行時に再課金される可能性があります。

GASの1実行6分の制限を想定し、4分の時間予算とAPI開始前の1分の余裕を設けています。10件ごとに保存し、時間ガードで中断すると時間主導トリガーで継続します。通信が予想以上に長引いた場合にも備え、各実行開始時に約7分後の継続トリガーを予約します。GAS側の都合で発火時刻は遅れる場合があります。進捗はシート上の結果を読み直して判定します。

継続対象のスプレッドシートID・シートIDを `AI_CLASSIFY_JOB` に保存するため、別タブを開いても元のシートを継続します。継続待ちに手動実行した場合も保存対象が優先されます。同一スクリプト内ではロックで重複実行を防ぎます。運用担当者1名で実行してください（トリガーは作成者ごとに所有されます）。完了・通常のエラー時は継続予約と保存対象を削除します。

停止したい場合はApps Scriptの「トリガー」で `continueClassification` を削除し、スクリプト プロパティの `AI_CLASSIFY_JOB` を削除します。実行中なら先に「実行数」から停止してください。通信1回が長時間ブロックする場合、時間ガードだけで強制終了を完全には防げません。UrlFetch・トリガー実行時間などの日次割り当てを超えた場合は、回復後に手動で再実行してください。

## トラブルシューティング

- **メニューがない**: 保存後にスプレッドシートを再読み込みしてください。
- **本文列が見つからない／重複**: 1行目のヘッダーと `TEXT_COLUMN` を一致させ、同名列を1つにしてください。
- **HTTP 400／401／403／404**: プロバイダ、対応するキー、利用可能なモデルIDを確認してください。`claude-sonnet-5` は指定の既定値です。アカウントで利用できない場合は `MODEL` に利用可能なIDを設定してください。プロバイダ切替時は `MODEL` も見直してください。
- **HTTP 429／5xx**: 利用枠・レート制限・サービス状況を確認し、時間を置いて再実行してください。
- **JSON／引用エラー、出力が未完了**: 該当バッチは空欄のままです。長すぎる本文やモデル設定を確認して再実行してください。
- **処理されない／続かない**: 出力セルの値・数式、Apps Scriptの実行履歴・トリガー・権限・割り当てを確認してください。エラー後は対象シートで「実行」を選んで再開します。

この移植作業ではAPIを呼び出していません。GAS上の実通信・権限承認・トリガー発火は、セットアップ後に確認してください。
