# 問い合わせ・自由記述をAI分類しExcel化

問い合わせフォームやメールで届く「自由記述の問い合わせ」を、AI（Claude / GPT）で
自動分類してExcelに整形するツールです。カテゴリ分け・要約・緊急度判定・返信案の
下書きまでを一括で行い、担当者は上から順に対応するだけの状態にします。

## これは何をするツールか

- 入力: 問い合わせのCSV/Excel（日時・顧客名・本文などの列を含む表）
- 処理: LLMに20件ずつまとめて渡し、以下の5項目を追加
  - **カテゴリ**（配送遅延・返品交換・不良品・請求など、業種に合わせて設定可能）
  - **要約**（40字以内）
  - **緊急度**（高 / 中 / 低）
  - **返信要否**（要 / 不要）
  - **返信案**（2〜3文の丁寧な下書き文）
- 出力: 見やすく整形されたExcel（ヘッダー装飾・自動幅・折り返し・ヘッダー固定・
  オートフィルタ・緊急度「高」の行を色付け）+「集計」シート（カテゴリ別/緊急度別の
  棒グラフ付き集計）+「実行ログ」シート（件数・コスト概算など）

## セットアップ

```bat
pip install openpyxl PyYAML anthropic
```

（OpenAIを使う場合は `pip install openai` も追加）

## 使い方

### 1. サンプルデータの生成（任意）

```bat
python make_sample_inquiries.py
```

`input/inquiries.csv` に100件のサンプル問い合わせ（架空のネットショップ宛て）を生成します。

### 2. AI分類の実行

```bat
python classify_to_excel.py input/inquiries.csv --out output/result.xlsx
```

主なオプション:

| オプション | 説明 | 既定値 |
|---|---|---|
| `--provider` | `anthropic` / `openai` / `claude-cli` | 環境変数から自動判定 |
| `--model` | 使用モデル名 | プロバイダごとの既定モデル |
| `--text-col` | 分類対象の本文カラム名 | `問い合わせ本文` |
| `--rules` | カテゴリ定義YAML | `rules.example.yaml` |
| `--batch-size` | 1リクエストあたりの件数 | `20` |
| `--dry-run` | APIを呼ばず `(dry)` でレイアウトのみ確認 | オフ |
| `--no-cache` | キャッシュを使わず全件再実行 | オフ |

環境変数 `ANTHROPIC_API_KEY` または `OPENAI_API_KEY` があれば自動でそのプロバイダを
使います。どちらも無い場合は、ローカルにインストール済みの Claude Code CLI
（`claude` コマンド）を使ったフォールバック（`--provider claude-cli`）で動作します。
このフォールバックは**オーナーのサブスクリプションを使うデモ生成専用**なので、
実運用では `anthropic` または `openai` を明示的に指定してください。

再実行時は `output/.cache/*.json` に保存された結果を再利用するため、途中で
中断してもAPIを呼び直さずに再開できます（`--no-cache` で無効化可能）。

### 3. ダブルクリック運用（Windows）

`run_classify.bat` をダブルクリックすると、ファイル選択ダイアログで入力ファイルを
選び、分類後に出力フォルダが自動で開きます（`gui.py` を使用）。
配布用exeの作り方は `build_exe.md` を参照してください。

## カテゴリのカスタマイズ

`rules.example.yaml` をコピーして自社の業種に合わせて編集し、`--rules` オプションで
指定してください。カテゴリ名・定義・返信案のトーン・緊急度の目安を自由に変更できます。

```bat
python classify_to_excel.py input/inquiries.csv --rules my_rules.yaml --out output/result.xlsx
```

## 品質を安定させる工夫

問い合わせ分類のような「決まったカテゴリに当てはめる」タスクは、モデルが独自の
表記ゆれ（カテゴリ名を言い換える、番号を取り違える等）を起こすことがあるため、
このツールでは以下の対策を組み込んでいます。

- カテゴリは文字列ではなく**番号（インデックス）**で答えさせ、表記ゆれを防止
- 各行の本文冒頭を"quote"として復唱させ、本文とAIの回答の対応を内容ベースで検証
- 本文中の明確なキーワードでカテゴリを一意に判定できる場合は、それを優先する
  キーワード照合をガードレールとして併用
- レスポンスのスキーマ検証・リトライ（指数バックオフ）・再実行用キャッシュ

## コストの目安

- Claude Haiku 4.5 相当のモデルで、問い合わせ100件・20件バッチ（5回のAPI呼び出し）の場合、
  **概算で数円〜数十円程度**（トークン量・モデルにより変動）。
- 実際のコスト概算は生成された `output/result.xlsx` の「実行ログ」シートに、
  推定トークン数・USD/円換算で記録されます。
- OpenAI/Anthropicの料金は変動するため、最新の料金は各社の公式ページをご確認ください。

## プライバシーについて

- 問い合わせ本文はカテゴリ分類・要約・返信案作成の目的のみに使用し、それ以外の
  用途では利用しません。
- 本ツール自体はログをサーバー等に保存しません（ローカルの `output/.cache/` に
  再実行用のキャッシュを保存するのみで、外部送信はしません）。
- 導入検討時は、実データの代わりに氏名・注文番号などをダミー化したデータで
  動作検証することも可能です（`make_sample_inquiries.py` が参考になります）。
- 送信先LLMプロバイダ（Anthropic / OpenAI）のデータ取り扱いポリシーは各社の
  利用規約をご確認のうえ、必要に応じてゼロデータ保持等の契約形態をご検討ください。
